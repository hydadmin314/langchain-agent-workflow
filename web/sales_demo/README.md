# 销售推荐 Demo 展示台

这是给业务部门演示销售推荐多轮交互、会话记忆、推荐就绪判断、产品打分和方案对比的页面。

## 打开方式

默认使用“本地预解析与排序 + 单次大模型理解与表达”模式。推荐通过单实例脚本启动，它会先关闭同端口的旧 Demo 进程，避免浏览器继续连接旧代码：

```powershell
.\web\sales_demo\start.ps1 -Port 8775
```

需要和旧版双调用流程对比时：

```powershell
.\.venv\Scripts\python.exe web\sales_demo\server.py --port 8766 --llm-mode double
```

浏览器访问 `http://127.0.0.1:8775`。

页面依赖本地 Python 服务。电脑重启、终端退出或服务进程结束后，需要重新执行上面的启动命令；浏览器页面本身不能直接调用大模型。

页面也可以直接打开 `web/sales_demo/index.html`，但此时仅用于本地交互预览，不会运行真实产品库评分。

## 当前范围

- 页面统一使用智能收敛策略：信息充分时立即推荐，信息模糊时逐轮澄清。
- 后端负责终止判断；无论信息是否完整，最多第 6 轮输出当前最优结果。
- 内置 8 个标准演示案例，覆盖产品推荐、产品对比、资费查询、办理流程和需求澄清。
- 每个案例包含预期分类、5 轮参考补充、第 6 轮推荐、预期主推、风险提示和禁止错误。
- 演示过程中可以点击“填入参考回答”，快速完成标准路径回归。
- 后端通过同事新增的 `SalesRecommendationWorkflow` 统一入口运行需求解析、会话合并、就绪度判断、追问、召回、过滤、打分、对比和推荐说明。
- 页面展示 Top 3、综合得分、加分依据、风险扣分、产品库处理数量和多维对比。
- 页面同步展示结构化需求画像、本轮新增字段、推荐假设、前后冲突和 Demo 层规则校正。
- 默认每轮只调用一次大模型；需求初稿、产品召回、过滤、打分和排序由本地程序完成。
- 单次模型同时补全业务语义，并生成自然追问或最终推荐说明。
- 模型请求失败时接口会明确报错，避免静默降级造成误判。
- 无网络预览时可添加 `--offline`，仅使用本地规则。
- 不修改主 agent 框架，不影响 `web/product_review` 产品 JSON 展示页。

## 接口

页面默认请求：

```text
POST /api/sales-demo/turn
```

请求示例：

```json
{
  "session_id": "sales-demo-example",
  "user_text": "餐饮门店5个人用，主要收银、外卖平台、监控和日常上网"
}
```

同一个 `session_id` 下，每轮只发送本轮新增的 `user_text`，后端会负责合并客户需求并保留冲突记录。
